# MV3 regression review — 2026-09-05

This review extends the popup-parity work with failure injection, direct comparisons against the bundled uBlock Origin filtering engine, and browser tests of the actual Chromium MV3 package. Upstream reports are reproduction guides, not evidence that every reported issue exists in this fork. No upstream issue was posted or modified.

## Reproduced defects and corrections

- **Settings persistence:** one rejected save poisoned subsequent saves; failed reads could be mistaken for a fresh install, and session state could override durable settings. Saves now queue independent snapshots, recover after rejection, and read authoritative local storage. Session storage is an optional cache.
- **Custom filters:** mutations returned before persistence, concurrent additions could lose selectors, and read failures could overwrite saved filters. Complete read/modify/write operations now serialize, propagate failures, and remain retryable.
- **Backup/reset:** a disabled site's remembered protection level was omitted, causing different results in fresh and existing profiles. Backups now carry that metadata; reset and legacy restore clear stale values. Malformed site scopes are rejected before restoration starts. DNR activation failures are surfaced, while an ambiguous lost response does not overwrite text paired with possibly committed rules.
- **Site controls:** a mode could commit before script registration failed, and retrying the same level skipped repair. Retries now refresh both script registrations and wait for both operations to settle before releasing the mutation queue.
- **IP sites:** wildcard-prefixed IPv6 match patterns were rejected by Chromium. IPv4 and IPv6 registrations now use exact host patterns.
- **Trusted child sites:** popup-script registration omitted child exclusions beneath an explicitly protected parent. Both global and explicit advanced-mode registrations now respect None/Basic exclusions.
- **Popup fail-open authority:** the legacy target-only closer bypassed the observer's trusted-opener checks; exact packaged EasyList/uBlock data reproduced it. Popup closure is now routed through the observer, which has opener, target and filtering-mode context. Incomplete context continues to defer.
- **Unpicker:** the background returned a selector count where the popup expected a boolean. Saved matching filters now enable the tool.
- **Keyboard operation:** setting the popup inert during a mutation moved focus to the body. Completion now restores the initiating control when it remains available.
- **Older Chromium:** deleting an unsupported top-site exclusion broadened a rule. Unsupported restrictive rules are omitted intact; unsupported allow exceptions prevent replacement, retaining the previous rule set. The regression matrix covers stock, sandbox and imported realms.
- **Developer DNR drafts:** partially invalid text could activate only the parsed subset or erase previous rules. Invalid drafts now return line-specific errors and preserve the active rules and draft text.
- **Offscreen compilation:** Chromium offscreen documents expose the extension runtime API, not storage. The compiler now uses acknowledged messages to its existing service-worker listener. Storage access is limited to the current generation and selected list cache/handoff keys. Failed or missing acknowledgements fail compilation, and cleanup waits for already-issued writes.

The popup matcher retains conservative deferred allows, missing-context deferral, important-rule precedence, evaluation budgets and stock popunder omission. No browser quota or HTTPS import requirement was relaxed.

## Reproducible coverage

`npm test` includes the previous compiler, fail-open popup policy, DNR durability, locale, memory, capability, navigation and transaction suites, plus:

- `test-settings-lifecycle.mjs`: authoritative reads, save rejection/recovery, queued snapshots and stale session caches.
- `test-custom-filter-storage.mjs`: awaited persistence, concurrent additions, read/write/delete failures and recovery.
- `test-backup-lifecycle.mjs`: fresh/existing profiles, interrupted journal, reset, scope preflight and activation response failures.
- `test-filtering-mode-retry.mjs`: actual background message handlers under registration faults, repair on retry, Unpicker data and IP match patterns.
- `test-upstream-popup-parity.mjs`: 16 request comparisons against fresh instances of the bundled upstream engine, including positive/negative target and initiator scopes, exceptions and important blocks.
- `test-user-dnr-drafts.mjs`: malformed and partially valid drafts, correction/retry, disabled developer mode and intentional clearing.
- `test-offscreen-storage.mjs`: actual compiler entry with runtime-only APIs, cold/warm/corrupt caches, acknowledged persistence, storage failure, generation/key restrictions and verified-source handoff.
- `test-popup-observer-authority.mjs`: trusted/intentional openers remain allowed, missing context defers, eligible stock matches close through the observer, and legacy registrations cannot bypass it. Passing the unpacked artifact path additionally checks the generated stock corpus and packaged scripts.

Release commands, package hashes, browser scenario outcomes and screenshots are recorded in the workspace's `tmp/full-retest/REPORT.md`. The package is built with the workflow's Node 22.22.0 and npm 11.19.1.

## Limits

This is a defined regression suite, not proof that every website or extension function is defect-free. The browser fixture suite uses a disposable Chromium profile and deterministic local/HTTPS-intercepted resources. It does not establish cross-browser parity, broad site compatibility, or assistive-technology certification. Native permission prompt dismissal requires a separate permission configuration. Whole-profile restore is sequential: invalid input fails preflight and individual operations have tested recovery, but a late external error can leave earlier settings restored. Existing injected scripts require a page reload after changing protection.
