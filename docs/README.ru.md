uBlock Plus+ — независимый блокировщик контента для Chromium MV3 под лицензией GPL. Он сочетает проверенную основу фильтрации и компилятора исходного проекта с общественным каталогом Filter Store, переносимой конфигурацией, явными настройками для опытных пользователей и бережным расходованием памяти. Проект не использует собственную телеметрию и не загружает исполняемый код из сети.

> [!IMPORTANT]
> **Состояние выпуска:** v1.0.0 — предварительная версия для ручной установки, которая не обновляется автоматически. uBlock Plus+ не является официальным выпуском uBlock Origin или uBO Lite и не одобрен Рэймондом Хиллом. Chrome MV3 предоставляет не все механизмы блокировки, доступные исходному расширению MV2. Ручная установка позволяет не зависеть от правил распространения Chrome Web Store, но **не** отменяет квоты DNR, жизненный цикл Service Worker или границы безопасности браузера. См. [честную таблицу совместимости](FEATURE-MATRIX.md).

### Установка выпуска

1. Загрузите `uBlock-Plus_*.chromium.zip` и соответствующий файл `.sha256` со страницы [GitHub Releases](https://github.com/kayurachann/uBlock-Plus/releases).
2. Проверьте контрольную сумму, затем распакуйте ZIP в постоянную папку.
3. Откройте `chrome://extensions` или `edge://extensions`.
4. Включите **Режим разработчика**, выберите **Загрузить распакованное расширение** и укажите распакованную папку с файлом `manifest.json`.
5. В Chrome 138 и новее откройте страницу **Сведения** расширения и включите **Разрешить пользовательские скрипты**. В Chrome 130–137 вместо этого используется общий переключатель **Режим разработчика**. Если после установки вы изменили любой из этих переключателей, нажмите **Обновить** на карточке расширения, чтобы контекст Service Worker увидел новое состояние API. Это позволяет регистрировать поддерживаемые импортированные косметические фильтры и встроенные скриптлеты из списка разрешённых. См. [руководство Chrome по `userScripts`](https://developer.chrome.com/docs/extensions/reference/api/userScripts).

> [!NOTE]
> Расширение, установленное вручную, не обновляется через Chrome Web Store. Следите за страницей [Releases](https://github.com/kayurachann/uBlock-Plus/releases) и заменяйте распакованную сборку после публикации новой версии. Устанавливайте только артефакты из этого репозитория и проверяйте предоставленную контрольную сумму SHA-256.

<details>
<summary><strong>Проверка контрольной суммы выпуска в Windows</strong></summary>

```powershell
(Get-FileHash .\uBlock-Plus_1.0.0.chromium.zip -Algorithm SHA256).Hash
Get-Content .\uBlock-Plus_1.0.0.chromium.zip.sha256
```

Шестнадцатеричные хеши должны совпадать; регистр букв не имеет значения.

</details>

### Сборка из исходного кода

Требования: Chrome/Chromium или Edge 130+, Git с поддержкой подмодулей, Node.js 22+ и доступ к сети для получения данных фильтров во время сборки.

<details open>
<summary><strong>Windows / PowerShell</strong></summary>

```powershell
git clone --recurse-submodules https://github.com/kayurachann/uBlock-Plus.git
cd uBlock-Plus
$version = (Get-Content -Raw package.json | ConvertFrom-Json).version
.\tools\make-mv3.ps1 -Platform chromium -Version $version
```

</details>

<details>
<summary><strong>Linux / macOS</strong></summary>

```bash
git clone --recurse-submodules https://github.com/kayurachann/uBlock-Plus.git
cd uBlock-Plus
make mv3-chromium

# Необязательно: также создать ZIP с версией и файл SHA-256.
VERSION=$(node -p "require('./package.json').version")
tools/make-mv3.sh chromium "$VERSION"
```

</details>

Загрузите `dist/build/uBlockPlus.chromium` со страницы расширений браузера. Команда PowerShell с версией и необязательная команда оболочки с версией создают ZIP и контрольную сумму в `dist/build/`; обычная команда `make mv3-chromium` создаёт только распакованный каталог.

## Как всё устроено

<div align="center">

<img src="assets/readme/feature-map.svg" alt="Поток фильтрации от выбранных пользователем источников через проверенную компиляцию к DNR и косметической фильтрации в Chromium" width="1100">

</div>

- Chrome DNR обрабатывает сетевую фильтрацию, не пробуждая Service Worker для каждого запроса.
- Событийный Service Worker управляет настройками, состоянием каталога, миграциями и восстанавливаемыми обновлениями правил.
- Импортированные списки локально компилируются в данные DNR и косметической фильтрации; скриптлет должен уже присутствовать во встроенном списке разрешённых.
- Компиляция в offscreen-документе выполняется временно, и документ закрывается после завершения работы.

## Безопасность и границы доверия

| Граница | Правило проекта |
| --- | --- |
| Удалённые источники | HTTPS-каталоги и списки разбираются как данные с ограничениями; перенаправления, некорректные схемы и исполняемые полезные нагрузки отклоняются. |
| Доверие к Filter Store | Встроенные и пользовательские записи показывают уровень доверия. Популярность в сообществе сама по себе не повышает запись до `verified`. |
| Код расширения | JavaScript, скриптлеты и ресурсы перенаправления поставляются внутри проверенного пакета расширения и никогда не загружаются по URL во время работы. |
| Разрешения | Основные разрешения фильтрации документированы. Разрешение Chrome `privacy` запрашивается только при включении соответствующих настроек и может быть отозвано. |
| Локальные данные | Настройки, скомпилированные фильтры и диагностика объёма хранилища остаются на устройстве, если пользователь явно их не экспортирует. |
| Целостность выпуска | CI собирает и проверяет артефакт Chromium; выпуски содержат контрольную сумму SHA-256. |

О проблемах безопасности сообщайте конфиденциально через [GitHub Security Advisories](https://github.com/kayurachann/uBlock-Plus/security/advisories/new), а не в публичной задаче. Правила отправки отчётов приведены в [SECURITY.md](../SECURITY.md).

## MV3: широкие возможности и честные ограничения

| Доступно сейчас | Ограничено MV3 | Возможные исследования в будущем |
| --- | --- | --- |
| Сетевая блокировка DNR, косметическая фильтрация, встроенные скриптлеты, пользовательские и импортированные списки, Filter Store, выбор и удаление элементов, контекстные политики всплывающих окон для отдельных хостов, применение наблюдателем упакованных stock-правил `$popup` и поддерживаемого подмножества импортированных фильтров `$popup`/`$popunder` с сокращёнными сведениями о происхождении (область, строка исходника, вид), резервное копирование и восстановление | Журналирование запросов в реальном времени, процедурные фильтры, асинхронное наблюдение за всплывающими окнами, семантика динамического брандмауэра, операции с заголовками ответа и поведение перенаправлений не обеспечивают точного паритета с MV2 | Адаптер Managed Enterprise и отдельно устанавливаемый нативный компонент с открытым исходным кодом — после RFC, согласия пользователя и проверки безопасности |

Поддерживаемое подмножество импортированных фильтров всплывающих окон теперь применяется средой наблюдения. Условия, которые нельзя представить точно—например, условия типа домена, метода запроса или заголовка ответа—явно остаются отложенными, а не аппроксимируются. Отложенные условия `allow` сохраняются как консервативные защитные проверки с fail-open: такая проверка может только отложить решение и никогда не должна приближённо разрешать или блокировать. Поскольку применение следует асинхронным событиям вкладок и навигации MV3, оно не равно точной синхронной обработке MV2. Динамические и сеансовые правила DNR совместно используют единый лимит в 1 000 regex-правил; отдельного лимита 1 000 для каждого хранилища нет.

Произвольная перезапись тела ответа, эквивалентная видимость DNS/CNAME и точная блокировка по размеру ответа недоступны через обычные публичные API расширений MV3. Некоторые конструкции фильтров MV2 нельзя преобразовать; прежде чем рассчитывать на эквивалентность, сверьтесь с таблицей возможностей. Совпадения фильтров всплывающих окон локально раскрывают только сокращённые сведения об области, строке исходника и виде. Компиляция импортированных сетевых списков записывает стабильные причины принятия или отсрочки и номера строк исходного файла, однако более подробный вывод этого отчёта в панели управления пока остаётся задачей из планов.
